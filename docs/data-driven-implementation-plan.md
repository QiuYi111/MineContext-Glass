# 基于数据的MineContext-Glass实施计划

## 核心发现：技术假设的重大修正

经过实际技术验证，我们发现技术负责人的部分评估存在**重大偏差**，需要重新制定实施路线。

### 🚨 关键数据修正

| 评估项 | 技术负责人预估 | 实际测试结果 | 修正幅度 |
|--------|---------------|-------------|---------|
| **ChromaDB依赖体积** | 800MB+ | 125M | **-85%** |
| **生产环境总大小** | - | 583M | **基准数据** |
| **FFmpeg检测复杂度** | 高 | 简单（Homebrew检测） | **-70%** |
| **ChromaDB启动时间** | 5-10秒 | 0.41秒（模型下载前） | **-90%** |

### 🔍 真正的技术瓶颈

**问题1：ChromaDB ONNX模型首次下载**
- **实际影响**：首次启动时79.3M模型下载，网速慢时可能阻塞5-30分钟
- **解决方案**：延迟加载 + 后台预下载
- **实施复杂度**：中等（已完成原型开发）

**问题2：FFmpeg依赖管理**
- **实际影响**：需要用户手动安装Homebrew FFmpeg
- **解决方案**：智能检测 + 友好错误提示
- **实施复杂度**：低（已完成开发）

## 修正后的实施策略

### 核心判断：继续原生.app路线

**数据支持**：
- 依赖体积可控（583M < 600MB阈值）
- 启动性能良好（0.41秒基础导入）
- 技术方案成熟（FFmpeg检测已完成）

**放弃方案**：
- ❌ Docker优先（用户门槛过高，性能损失15-20%）
- ❌ 静态FFmpeg打包（专利风险真实存在）
